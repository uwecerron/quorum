# Quorum vulnerability review — September 13, 2026

Scope: application code on feat/dao-coverage, based on commit 626112b, the API, GoldRush integration, dependency lockfile, and browser rendering. This was a local source review and regression test process. No production load tests, live-key calls, deployment configuration inspection, or DAO contract audits were performed.

## Findings

1. **Medium: malformed upstream data can produce a plausible score (fixed).** Reproduced by calling combineGass with NaN total supply: the original implementation returned GASS 46 with null totalSupply. Missing treasury items also defaulted to a zero balance, and string quotes could concatenate during summation. The scorer now validates units, positive supply, finite numeric inputs, supply bounds, and treasury quote types, and rejects missing items. Regression tests cover invalid supply, malformed units and absent balance data. This is an upstream-data trust issue; arbitrary callers cannot directly supply scoring inputs through the API.

2. **Medium: public scoring endpoint can amplify provider usage (partially mitigated; deployment action remains).** Every origin invocation previously requested GoldRush data with no request timeout or server-side reuse. CDN cache misses, non-GET requests and query variations could trigger more requests. GET-only handling, query validation, an eight-second timeout per upstream call, and a five-minute per-DAO cache with concurrent request coalescing now reduce this exposure. The cache is bounded by registered live DAO IDs. Failed requests are not cached. Shared rate limiting, provider spending limits and/or a Vercel WAF policy remain necessary: warm-instance caching does not prevent distributed abuse or repeated retries during an upstream outage. Production WAF configuration was not inspected or changed.

3. **Low: upstream error bodies flowed into server logs (fixed as hardening).** Provider response bodies and error messages were incorporated into thrown errors and logged. No actual key leak was observed. Upstream errors are now sanitized; API logs identify only the DAO and generic failure, and clients continue to receive generic errors. Redirect following is disabled for authenticated provider requests.

## Other checks

- npm audit queried the advisory database: zero known vulnerabilities (71 dependency entries reported). This is not a guarantee against undisclosed vulnerabilities.
- Reviewed browser code for dangerous HTML sinks and secret handling. No dangerous HTML rendering sink was identified in the searched application code. React renders coverage labels as text.
- API IDs are allowlisted through own-property checks; clients cannot supply upstream URLs or contract addresses through this endpoint.
- No wallet signing, fund transfers, database queries or shell execution paths were found in the reviewed scoring API.
- A targeted scan of tracked files for GoldRush keys, GitHub tokens and private-key headers returned zero flagged files. This is a pattern scan, not a comprehensive git-history or credential audit.
- Ten regression tests pass; production build passes; lint has one pre-existing ReplayTimeline state-in-effect warning.

## Remaining product limitations

GASS uses configured quorum assumptions and holder balances, not current delegated voting power or a verified execution path. Research coverage for 16 DAOs is not live scoring. Historical treasury classifications are source-reported, not verified liquidity or funds reachable through governance. No named DAO vulnerability is established by this application review.

## Reproduce

From app/: run `node --test`, `npm run build`, `npm run lint`, and `npm audit`. Security regressions are in app/test/security.test.js. npm audit requires network access. Live integration and deployment tests require separate credentials and deployment access.
